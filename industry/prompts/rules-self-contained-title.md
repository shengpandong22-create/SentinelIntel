【标题自洽规则 — 让读者不点开就知道"这是关于谁的什么事"】

1. 标题必须点出核心主体：厂商名 / 产品名 / 型号 / 漏洞编号 / 标准编号 / 项目名。
2. 原标题已经清楚点出主体的：英文标题翻译成中文、中文标题保持原意，不要为改写而改写。
3. 原标题只是版本号 / 代号 / 没信息量的 teaser（如 "V5.7.3"、"Security Update"、"Advisory"、"Important Notice"、"重磅发布"）时，结合【来源】和正文把主体补进标题。例：原标题 "Cisco Security Advisory" + 来源和正文明确是 IOS XE → "Cisco 修复 IOS XE 一处漏洞"。
4. 补主体只能用【来源】或正文里真实出现的名字。正文和来源都没点出具体型号时，用上位词（如"网络摄像机固件""边界设备"）兜底，绝不凭"行业常识"编一个具体型号 / 版本 / 漏洞编号 / CVSS 分数。
5. 原标题表达的【文章类型和核心动作】是硬边界：How / Why / Guide / Analysis / Review / Best Practices 这类解释、分析、指南或评测标题，中文标题必须保留这个类型；不能因为正文谈到一个已经存在的漏洞、产品或修复，就改写成"披露 / 发布 / 修复 / 上线"。只有原标题或正文明确宣布了披露、确认、发布或中标，中文标题才能使用对应动作。保留文章类型不等于删主体：仍须按第 1-4 条补全正文或来源明确给出的厂商、产品、型号或漏洞编号。
   例：原标题 "How to harden NetScaler ADC against session hijacking" → "NetScaler ADC 如何防护会话劫持"，不能写成 "Citrix 发布 NetScaler ADC 修复补丁"。
   例：原标题 "Understanding GB/T 28181 authentication" + 来源和正文明确是视频监控联网标准 → "GB/T 28181 的认证机制解读"，不能只写成缺主体的 "认证机制解读"。
