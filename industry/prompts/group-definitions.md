SAME_OCCURRENCE（同一次发生）：同一个主体在同一时间对同一批对象做的同一件事。跨语言转述、不同媒体的不同侧重、细节多寡不同、官方原文与媒体报道、官方公告的不同转载与翻译，都算同一次发生；同一份公告、同一份标准或法规文件、同一份判决、同一起事故、同一次招标的重复报道，也算同一次发生；同一厂商在同一份公告里一并给出的多个受影响产品线、多个型号、多个固件分支，以及这次公告里的受影响范围、修复版本、缓解措施、CVSS 分数，都算同一次发生。

SAME_STORY（同一事件的不同进展）：不是同一次发生，但围绕同一个具体漏洞、事件、项目或文件有直接的先后关系。安防与安全行业至少包括这些情形：
- 漏洞披露 → 厂商确认：研究方或媒体先披露，厂商随后确认或说明，是同一漏洞的后续进展。
- 漏洞披露 → 补丁与修复版本：首次披露之后发布补丁、给出修复版本、更新固件分支。
- 漏洞披露 → PoC 与在野利用：后续出现概念验证代码、被观察到在野利用、被纳入已知被利用目录。
- 同一漏洞的多厂商公告：同一个 CVE 或同一个上游组件漏洞，被不同厂商各自发布公告；这是同一漏洞的不同厂商进展，不是同一次发生。
- 同一份公告的修订：同一份公告或公告编号的新版本、范围更正、状态更新（例如从“正在调查”改为“已确认”）。
- 招标公告 → 中标结果：同一次采购从招标、开标、澄清到中标、成交、终止的先后关系。
- 政策与标准的状态推进：征求意见稿 → 正式发布 → 修订 → 明确的实施日期，是同一文件的先后阶段。
- 事件 → 官方后续：安全事件发生之后，厂商、监管机构或 CERT 的官方调查、通报、处置说明与追加声明。

UNRELATED（不同的事）：不同的漏洞、不同的事件、不同的项目、不同的文件，即使出自同一厂商、同一产品、同一型号或同一份汇总。安防与安全行业至少包括这些情形：
- 同一厂商的不同 CVE：同一厂商或同一产品的两个不同漏洞编号，属于两件事，即使同一天发布、出现在同一份月度补丁汇总里。
- 同一产品的不同漏洞、同一型号的不同漏洞。
- 不同厂商各自不同的漏洞。
- 与漏洞无关的普通版本更新、功能发布、公司经营、人事、融资。
- 只是提到同一个厂商、产品、型号、标准或漏洞编号。关于某产品的加固教程、用法分享、个人观点、营销帖，除非明确针对候选那一次具体披露（复现它、回应它、修复它），否则是 UNRELATED。
- 同一话题的不同研究、不同观点、不同事件。

ROUNDUP：其中一方是多话题盘点、月度补丁汇总、日报、周报、早报、安全周报，把对方的事件作为多个条目之一。
